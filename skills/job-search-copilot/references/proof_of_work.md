# Proof of Work — the stand-out artifact

A tailored resume is table stakes; in a flooded applicant pool it lands in the same pile as everyone else's. Candidates stand out by **showing upfront that they can do the job** — attaching evidence, not just claims. This is the single highest-leverage move a strong applicant can make, and almost nobody does it.

Use this reference when offering or building a proof-of-work artifact in Phase 5. The whole point is *show, don't tell* — so the artifact must be something a hiring manager can open and immediately see the candidate operating at the level of the role.

## Function → artifact map

Match the artifact to the **listed job's function**, not the candidate's favorite thing to make. Pick the one that most directly evidences the core responsibility in the job description.

- **BD / Sales / Partnerships** → a **target-account teardown**: 5-10 named accounts the candidate would pursue for *this* company, each with the specific angle/hook and why it fits the company's ICP. If the candidate genuinely has a track record, add a short **"accounts already converted"** list — real logos and real outcomes only.
- **Ops / BizOps / Strategy / Analytics** → a **working tool**: a spreadsheet model, a script, a dashboard mockup, or a written SOP that solves a real problem the company likely has. Bias toward something they can actually run or paste in and use.
- **Marketing / Growth / Content** → a **campaign teardown or sample asset**: a critique of their current funnel with fixes, or a real deliverable (landing-page copy, a 3-email sequence, a content calendar, an ad-angle set).
- **Customer Success / Support** → a **mock onboarding flow, a macro/help-doc set, or a churn-analysis approach** built around the company's actual product.
- **Recruiting / People / Talent** → a **sourcing plan, a scorecard, or an interview-loop design** for a role the company is hiring.
- **Product-adjacent / other** → a **30-60-90 day plan** for the listed role, or a **mini-analysis of one concrete problem named in the JD**. (See the focus rule below — this is *not* a product-vision deck unless the listed job is a product role.)

When the function isn't obvious, ask the user what the core deliverable of the role is and map from their answer.

## Honesty guardrails (inherit the skill's non-negotiable rules)

These apply to every proof-of-work artifact, without exception:

1. **Only real, evidenced work is presented as done.** A list of "accounts converted," a metric, or a shipped result must be something the user actually did and can defend two levels deep in an interview. Never fabricate logos, numbers, or outcomes.
2. **Label hypotheticals as hypotheticals.** Prospective work — accounts they *would* pursue, a tool they've *built for this application*, a plan they *propose* — is framed as *"here's how I'd approach it,"* never dressed up as completed experience. In-progress work is "currently building," not "shipped."
3. **Focus on the listed job.** The artifact must map to the role's stated responsibilities. Off-target flourishes (product ideas at a company with no product roles, a growth deck for an ops job) don't show fit for the actual job and can read as not-listening. Before building, check the artifact against the JD's real function and cut anything that doesn't serve it.
4. **Respect no-AI policies.** If the posting or company asks candidates not to submit AI-generated content, deliver the artifact as **raw reference material the user must substantively rewrite/rebuild in their own words**, and tell them so plainly. Never help present AI-generated work as the candidate's own where it's been prohibited.
5. **Right-size the effort.** Favor artifacts Claude can genuinely produce well end-to-end — a spreadsheet, a script, a written teardown or plan. For heavy "build a working tool" asks that exceed what's reasonable to finish here, deliver a **working starter + a short spec** and tell the user what to complete, rather than a hollow mockup.

## Delivery

Deliver as a real file when the environment can generate one (same fallback rule as the resume phases: clean copy-paste text/Markdown when it can't, stated plainly). Name files consistently, e.g. `Firstname_Lastname_ProofOfWork_Company.xlsx` / `.md` / `.pdf`. Log the artifact in the tracker's **Proof of work** column so nothing is duplicated across a batch.
